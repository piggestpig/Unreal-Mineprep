# 渲染输出面板

Filmic 视频编码及 HDR 图片转换／合成开始时立即显示编辑器右下角任务提示，同一次处理切换阶段时更新文字。取消会终止当前外部进程并停止后续阶段，保留输入及日志，返回未完成；原生 MRQ/MRG 内部编码仍由引擎管理。

单页工作台按“当前任务 → 渲染队列 → 特殊工具”排列。默认使用 MRQ，可选 MRG；布局主要在 `panel.py::draw()` 创建，不切换页面，也不要求先保存预设才能入队。画质、采样和编码等参数继续从旧蓝图面板采集。

## 操作

1. 在旧“渲染输出子面板”调整画质，打开所需序列。
2. 选择任务：动画、静帧或 HDR JPG。可以调整序列、输出名、静帧帧号；HDR JPG 显示 SDR／HDR 质量。
3. 点击“+ 加入队列”，或“立即渲染”。后者直接执行当前任务，不写入队列、不改名，已有输出沿用覆盖规则。
4. “开始队列”按当前顺序执行所有已启用的待渲染项。

“当前设置”在点击“采集”、入队或立即渲染时重新读取旧控件的画质参数，并更新“最近采集”摘要。入队和渲染时，序列、输出名和帧号使用编辑区显示的值，不因外部切换序列、拖动光标而暗中替换；缺少相机轨道时仍沿用临时序列回退，并同步显示第 0 帧。点击“光标”同步所选序列的时间线帧，点击“采集”则同时同步参数、当前序列和光标。摘要不是实时监听；已保存预设继续使用保存的参数。旧面板未打开时，初始化仅显示行内提示；已保存预设可独立执行动画／静帧。

底部“特殊工具”默认收起，包含 **Filmic HDR 视频**、图片合成和再次折叠的原 HDR 流程。队列刷新不会收起这些区域。图片工具与主任务的 SDR／HDR 质量共用同一组值，修改任一处会同步另一处。

**渲染 Filmic HDR 视频** 按钮仅用于普通动画，沿用当前任务的序列、输出名、分辨率、帧率、采样和暖场。0.7.3 改为 UE 原生输出 Rec.2020 PQ EXR，FFmpeg 只转换到 YUV 后编码为 H.265 Main10 MP4，不再重复应用 PQ。保留 MRQ、1000／203 nit 默认目标、无音频和独立输出目录，不切换旧 HDR 控件；硬件和质量选择见下文。C++ 设置新增 Output PQ 开关，关闭可保留 scRGB；仅临时选择 Filmic，其余 CVar 由用户控制，峰值遵循引擎全局覆盖规则。

临时入口不加入批量队列或预设库，不改原生 MRQ 队列和原配置资产。输出为 `Saved/MovieRenders/<原子目录>/<名称>_FilmicHDR/<唯一目录>/<名称>_FilmicHDR.mp4`，保留 EXR、`encode_command.json` 和 `encode.log`。占用标记保持到编码结束；在 UE 窗口取消后，已有连续完整帧仍可编码为部分视频，但返回 `success=False`，不播放成功提示。详见 [NATIVE_HDR.md](NATIVE_HDR.md)。

队列使用统一表头：启用、输出名、类型／后端、序列、规格、状态和操作。动画规格显示尺寸和序列当前帧率（或自定义帧率），静帧显示尺寸和帧号；长名称裁剪，悬停查看完整内容。每行提供“复制”、`↑ ↓` 排序、`×` 移除和目录按钮；未完整完成、失败或上次中断的项还提供 `↻` 重新排队。重试槽位始终保留，状态及按钮列保持对齐。错误简述显示在行下方，悬停查看完整内容。复制只在存在输出冲突时改名，重试沿用原路径及覆盖规则。

表体按内容自然增高，最多 360 Slate 单位（约 10 行），更多任务在表内滚动；表头、底部进度／运行栏和特殊工具均在表体之外。空队列只显示一行提示，不预留大块空白。

队列标题旁直接提供持久化的“成功后移除”，默认关闭，每批开始时固定此选项。完整渲染、编码及 HDR 合成收尾之后，先记录结果并执行逐项回调，再移除成功项；批次返回结果仍保留完整记录。失败、取消及未完整完成的项保留。目录与提示音仍沿用现有偏好。

运行时可新增任务、调整后续项的顺序和启用状态，也可移除后续项；渲染中或编码中的项不能移动、移除或改写，但可以复制。每项提交前重新取首个启用的待渲染项，已启动项的参数保持不变。“本项后停止”停止提交新渲染，等已启动的渲染和编码收尾；立即取消渲染仍用 UE 渲染窗口，后台编码使用右下角提示的取消按钮。任意一项失败或取消后停止提交后续项；已经启动的其他任务正常收尾，不强制终止。

关闭工作台不停止渲染。整批期间只在结束时按现有偏好打开目录和播放提示音；失败／取消不播放成功提示。运行时拒绝卸载／重载本模组，空闲时支持正常 `mineprep.reload()`。重启后，上次运行中的项标为“上次中断”，不自动执行。

## 预设与存储

带标签的来源下拉框同时提供“当前设置”和已有预设，旁边的“预设”展开名称及新建、更新、改名、删除操作。预设保存任务类型、后端、参数、地图、实际序列路径，以及静帧帧号／HDR 质量。更新预设不影响队列副本；从 HDR 预设重复保存、入队不会重复增加暖场。

- 预设库：模组目录内的 `presets/`，一个预设一个 JSON，如 `presets/a.json`。文件名使用预设名称，替换文件名非法字符；改名同步文件名，删除只移除对应文件。文件名冲突时报错，不覆盖其他预设。
- 队列：`<工程>/Saved/Mineprep/RenderPanel/queue.json`。
- 文件为 UTF-8、`schema_version=1`，通过临时文件替换写入。单个预设 JSON 的顶层包含 `id`、`name`、`backend`、`kind` 和 `settings`；旧记录缺少 `kind` 时按动画处理。ID 保持稳定，改名或删除预设不会改写已入队的参数副本。
- 首次读取时自动迁移旧的 `<工程>/Config/Mineprep/RenderPanel/presets.json`，保留原 ID 和参数，已有相同 ID 的新文件优先。全部写入并重新读取校验后，旧合集移到 `<工程>/Saved/Mineprep/RenderPanel/presets.legacy.json` 备份；已有备份时追加唯一后缀。迁移失败保留旧合集，下次可继续。发布模组时可按需选择随附的预设文件；它们仍保留原地图与序列引用，不会自动适配其他工程。
- 执行器、委托和临时配置保留在内存。MRQ 和 MRG 提交前保存脏资源，直接使用本次的临时配置。
- 「当前设置」从蓝图面板采集「渲染游戏模式」，将类路径保存在预设和队列中。旧记录缺少 `game_mode` 时使用引擎的 `MoviePipelineGameMode`，空字符串表示沿用关卡的游戏模式。
- 执行时检查地图一致，不自动切换；序列内容、播放范围和非自定义帧率取资产当前值。机器路径、编码器路径和通知偏好取执行环境，不写进预设。
- 入队时复制参数，只检查待渲染／渲染中任务的输出目标：视频容器、图片格式与静帧帧号、增益图独立后缀。存在冲突时分配 `_02`、`_03` 等后缀；已结束记录不占名，排序不改名。动画图片序列与同名同格式静帧会避让，两个不同帧的静帧不互相占名。立体／分层的同干名同格式输出仍保守避让。现有磁盘文件按原覆盖规则处理。

## 三种任务

### 快速预设

内置 `quick_image.json`（快速图片）与 `quick_video.json`（快速视频），均使用 MRQ、「快速预览渲染模式」、GPU 暖场 30 帧和 1×1 采样，关闭 HDR、全景、立体、分层、音频、后台编码及 DLSS／FSR。

- 快速图片：1920×1080 PNG，不转码，默认名称 `QuickRender/Image`。
- 快速视频：1280×720、30 fps，使用现有 UE 原生 H.264 MP4 路径，默认名称 `QuickRender/Video`。

在面板选择快速视频时，若 Sequencer 未打开任何序列，自动选中 `MC临时序列`，按其播放范围渲染（当前为 3 秒）。若已打开的序列没有相机切换轨道，面板会提示选择序列。

这两个预设使用 `context: "current"`：选择或通过 API 调用时解析当前地图与序列。界面随后仍使用显示的序列、输出名和帧号。更新通用预设只保存规格，不固化场景目标；新建普通预设仍保存具体场景。`slug` 指定稳定英文文件名，修改显示名也不改变它。普通预设未声明这些元数据时沿用原有行为。

`name` 支持普通字符串或类似 `mod_manifest.toml` 的语言字典，例如 `{"zh": "快速图片", "en": "Quick Image", "zh-Hant": "快速圖片"}`，字典须含 `zh` 原文。界面复用 Mineprep `i18n`，以 `presets.<id>.name` 为稳定 key，现有 `i18n.json` 译文优先；参数更新保留多语言名称，手动改成其他名称则使用新的普通字符串。API 推荐按英文文件名调用，不依赖界面语言。

**动画**沿用现有 MRQ／MRG 参数、视频编码、色彩、输出命名和目录规则。MRG 暂不支持旧式立体／Actor 层／数据层分层；全景不能与 DLSS 组合，当前 DLSS 插件的 MRG 节点仅接受平衡档。MRG 暖场和游戏画质仍遵循其自身机制，与旧 MRQ 并非逐项等价。

### 后台编码与图片转码

旧面板 `渲染输出子面板.🔲后台编码` 决定视频编码和图片转码的执行方式，点击时采集并固定：

- 关闭：保留 MRQ／MRG 自身管理的编码，普通动画继续自动选择内置 MP4／ProRes 或 CLI FFmpeg；Filmic HDR 使用 MRQ CLI FFmpeg。静帧转码仍由 Python 执行，但同样等待处理完成后才释放渲染占用。
- 开启：所有视频编码和图片转码改由 Python 后台管理 FFmpeg。UE 只生成图片／音频，完成委托立即提取普通 Python 文件路径；执行器清理后释放渲染占用，允许下一项开始。视频、静帧和图片序列转码共用两个后台进程名额，额外任务等待空位。HDR 增益图合成流程不变。
- 渲染、编码分别占用状态，任务句柄和队列项直到编码结束才完成；完成回调、成功移除和整批提示同样等到完整收尾。旧后台任务结束不会清除下一项渲染的占用。
- 普通视频、静帧、图片序列分别使用独立 `cache/RenderPanelVideo`、`cache/RenderPanelStill`、`cache/RenderPanelImages` 子目录，防止新渲染覆盖正在处理的输入。同名输出在后台处理期间拒绝再次提交，但同名不同帧的静帧可以连续渲染。成功后按“删除原图”选择清理缓存或将原图／音频发布到原输出目录；原图不会覆盖刚生成的同名转换结果。失败／取消保留缓存、日志及已有部分输出。
- 每个任务独立显示可取消提示，完整命令用 `unreal.log` 输出并记录在缓存中。后台运行期间拒绝重载模组；关闭面板不会停止任务。
- 开关和硬件随配置保存；旧 JSON 配置缺少开关时按关闭处理，需要重新采集覆盖才能启用。后台模式中的 ProRes 使用 MOV 容器。

Filmic HDR 临时入口仍输出 HEVC Main10／Rec.2020 PQ，不随普通视频格式改成 H.264 或 AV1；硬件和质量取旧面板，支持 CPU／Nvidia／Intel／AMD／Apple／Vulkan 对应的 HEVC 编码器，不静默回退。CPU 继续用 x265 的 mastering SEI；硬件路径写入 PQ／BT.2020 VUI 与容器标记，`master-display` 容器元数据不能等同于编码器已生成同样的 mastering SEI。EXR 始终保留。

0.8.0 集中验证：离线覆盖两项渲染／编码交接、并发上限、取消、占用隔离、编码器选择与实际输入命令；合成图片实测 H.264／H.265／AV1／ProRes，以及并行的 CPU／Nvidia Filmic HEVC，后两者均为 Main10、PQ、BT.2020。Intel／AMD／Apple／Vulkan 未在本机实测。没有执行实际场景渲染，队列视觉与最终 HDR 观感仍由用户验收。

**静帧**使用所选帧，关闭视频、音频和自定义帧率，保留旧面板的图片格式、图片转码、质量及删除原图选项。保留分辨率、色彩、采样、暖场及后端支持的全景／立体／分层设置。MRQ／MRG 都使用 `[frame, frame + 1)` 范围，以序列显示帧率解释帧号；文件名保留实际帧号，如 `MC.0120.png`。缺少序列或相机切换轨道时沿用临时序列第 0 帧。

静帧转码不使用原生 CLI 编码器：渲染结束后，只处理本次 UE 完成委托返回的文件，沿用原有转换滤镜和质量；转换后的 WebP／AVIF 等也保留帧号。先写独立缓存，检查输出后替换目标，支持 PNG 输入／输出同名；全部成功后才按选项删除源图，保留作为最终输出的同名文件。失败或取消保留输入与日志，不播放成功提示。转码阶段复用右下角可取消提示，句柄直到转换结束才完成；开启后台编码时会提前释放渲染占用。

**HDR JPG**固定 MRQ，一个队列项完整执行 SDR → HDR → 转换／合成。宽高向下取偶数，暖场额外 20 帧，无伽马调色。

- SDR：旧 HDR 复选框 `.select(0)`、色彩选项 `.select(0)`、PNG。
- HDR：`.select(1)`、色彩选项 `.select(1)`、EXR，OCIO 为 Rec.2100 PQ／Rec.2020、ACES 2.0 HDR 1000 nit。
- 使用旧控件事件触发场景后期处理，所以双次渲染期间必须保持旧面板打开；阶段间不释放整个任务的占用。开始前保存场景，结束后恢复临时改动。
- 临时切换期间禁用从“当前设置”刷新／采集任务，避免误将中间状态存为新任务；仍可从已保存预设入队。
- 每次独立缓存，FFmpeg／Ultra HDR 进程真正退出并验证输出后才结束。失败保留缓存；取消后只有具备完整输入才继续合成。输出为 `Saved/MovieRenders/<名称>_Gainmap.jpg`。

“图片工具”位于底部“特殊工具”内，保留已有 SDR／HDR 图片合成、原双通道 HDR 流程和 Gamma 参数；与主任务共用同一组 SDR／HDR 质量，不注册额外菜单或窗口。已有 HDR 输入须为 PQ／Rec.2020、1000 nit，不转换普通线性 EXR；取消文件选择直接结束。

## Python 接口

按文件名（可省略 `.json`）、ID 或任一语言的名称直接渲染，无须打开工作台或旧面板：

```python
from mods.RenderPanel import ops

task = ops.render_preset('quick_image', viewport=True)
```

视频是另一个独立示例；同一编辑器须等待上一项 `task.done` 后再提交下一项：

```python
task = ops.render_preset('quick_video', sequence='/Game/seq', fps=60,
                         warmup=10, name='QuickRender/Test')
```

`render_preset(preset, *, sequence=None, frame=None, name=None, viewport=False, on_done=None, notify=True, **overrides)` 不入持久队列、不自动改名，返回现有 `done / result / error` 句柄。覆盖仅影响本次调用，不修改 JSON 或旧控件。支持已有画质／编码参数（如 `width`、`height`、`warmup`、`spatial`、`temporal`、`quality`），未知字段报错。

`fps=60` 是 `custom_fps=1, fps_value=60` 的简写，不能同时指定这两种形式；本入口的自定义帧率须为正整数，小数不静默截断。静帧始终使用序列帧率。

显式 `sequence` 优先；否则通用预设使用当前序列，普通预设使用保存的序列。静帧默认取当前序列光标，显式选择另一序列时默认取其播放起点；`frame` 可覆盖。没有有效相机序列时，通用静帧回退临时序列第 0 帧，通用视频提示选择有效序列；显式指定无相机切换轨道的序列会报错。

`viewport=True` 优先于 `sequence`，固定当前地图和临时序列，沿用其自动对齐视口摄像机的行为；静帧固定第 0 帧，视频使用临时序列自身范围（当前 3 秒），不播放另一条序列的动画。视频不接受 `frame`，临时视角静帧不接受非零帧。不会修改临时序列资产或加入额外时长参数。

通过队列执行通用预设时使用 `batch.edit_queue('enqueue', preset_id)`，在入队时固定上下文；执行时不再次切换到新的当前序列。

Filmic HDR 的独立 MRQ 实验入口见 [NATIVE_HDR.md](NATIVE_HDR.md)：默认 Rec.2020 PQ，单帧接口可通过 `output_pq=False` 保留线性 scRGB（1.0＝80 nit）。临时视频入口 `native_hdr.render_video(settings=None, on_done=None, notify=True)` 明确使用 PQ，返回现有异步任务句柄。

以下采集／构建调用不启动渲染，不修改原配置资产或 UE 队列：

```python
from mods.RenderPanel import ops, mrg, hdr, batch
s = ops.capture_settings()
config, folder = ops.build_config(ops.prepare_settings(s))
still = dict(ops.still_settings(ops.prepare_settings(s), 129), single_frame=True)
graph, folder = mrg.build_config(still)
```

旧面板可以直接调用以下 API，无须打开 RenderPanel 工作台；本次没有修改蓝图连线：

```python
name = ops.reset_output_name()
config, folder = ops.update_render_config()
config, folder = ops.update_render_config(settings=s, preserve_extra=False)
```

`reset_output_name()` 只写回旧名称文本框并返回名称。格式为 `序列名_宽x高_帧率fps`，保留相对子目录、中文及色彩／VR／3D 后缀。使用聚焦序列，无序列时使用地图名；序列帧率保留小数，如 `29.97fps`，名称不带扩展名。

`update_render_config()` 返回临时配置和输出目录，并更新会话编码器与导播台 HDR 状态。旧 `Mineprep自定义渲染配置` 资产仍存在时，此接口也会保存它，默认 `preserve_extra=True` 保留额外设置，`False` 完整替换。显式设置直接用于构建配置。运行中的任务／批次会阻止手动更新。

MRQ 实际提交使用新建的临时配置。`build_config()` 可用于单独预览该配置。

以下调用**会启动实际渲染**，句柄支持 `done / result / error`，完成回调在任务释放占用后执行：

```python
task = ops.render_animation(settings=None, on_done=None, notify=True)
task = ops.render_still(settings=None, backend='MRQ', on_done=None, notify=True)
task = mrg.render_animation(settings=None, on_done=None, notify=True)
task = hdr.render_current_frame_twice()
task = batch.run_queue(on_item_done=None, on_done=None, remove_completed=None)
# None 沿用已保存的“成功后移除”偏好，True/False 可显式覆盖。
# 仍可只执行指定的已排队项：
task = batch.run_queue(item_ids=[item_id])
```

取消／未完整完成正常返回 `success=False`；Python 配置、提交或外部进程错误进入 `error`。`task.destroy()` 只停止 Python 协程，不是 UE 的取消操作。
